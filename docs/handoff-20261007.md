## Goal

Ship stock Kokoro-82M on the Hexagon DSP (SM8550, SM8635), whole model on HMX/HVX, integer,
PowerShell-emitted. Quality bar: about 40 dB raw PCM SNR against the stock capture (judged by ear as
indistinguishable; see `docs/results/tail-quantization-boundaries-20261007.md`). Scope decided by the
team: once the 16-bit 128-channel stage lands near the timing target, finish the rest of the model,
clear blockers (SM8635 tiled path, streaming AAudio host) and ship. Comparison boundaries (keep them
separate): phonemes -> PCM; text -> first audio; sustained.

Public reference points (not ours, different timing boundaries): QNN SM8650 generator RTF 0.2644 and
306 ms request -> first audio; mattmireles CoreML A17 Pro RTF 0.128-0.152 (token IDs -> PCM); Soniqo
iPhone 16 Pro RTF 0.08; Jon-Schneider CoreML ANE iPhone 16 Pro RTF 0.059 (precomputed phonemes).
Our phones are 2-3 generations older.

## Where the time goes

HMX is nearly idle. The frozen worker's profile measured raw HMX conv arithmetic at 2.03 ms for the
128-channel stage's 16.1 G MAC (5.89 TMAC/s effective; `generator60x-profile-breakdown-sm8550-20261006.md`),
and one more stage-wide HMX pass costs 1.9 ms. The 86.05 ms stage therefore averages 187 GMAC/s; the
rest is HVX elementwise work and data movement on one HVX thread at one instruction per packet. After
the 16-bit stage is correct, the speed work is: VLIW packing of the HVX bodies (limits are the four HVX pipes;
see docs/hexagon-v73-notes.md), more HVX threads (verify the SM8550 HVX context count first), DMA overlap. The
goal is to bring the stage toward its HMX floor; measure, do not project.

## Tooling language

Product code is PowerShell (emitters write the DSP machine code); C files are simulator harnesses only.
Python is for executing stock PyTorch Kokoro (captures, quantization sweeps that run the stock model).
Author and edit files, and analyze results, in PowerShell or with direct edits, not Python scripts.
The port of the 11 capture-consuming Python tools to PowerShell is an open task.
