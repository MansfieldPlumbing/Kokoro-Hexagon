## Faults found and fixed this session (each now a check)

1. Weight tensors in VTCM at 0x400 mod 0x800 (the word rows came first): HMX `:deep` 2 KB weight loads straddled a page;
   ffn's crossed 4 MiB at 0xFF3FFC00: QuRT cause 0x26 (V73 PRM 8.10, "Coprocessor VMEM address error"), FastRPC
   0x8000040D. Located from the logcat CDSP crash report (fault PC mapped to the emitted step, bad VA to the layout).
   Fix: every weight tensor 4 KB aligned and none straddles a 4 MiB boundary; `Get-KokoroAlbert16Layout` throws
   otherwise.
2. Conv input windows at the stream LSB: A1 (sized for a1 + ffn_output) used about 1/10 of its 16 bits, L fell to 2..5,
   and the two accumulator groups' low-byte offset (127.5 input LSB x the weight row sum) overflowed their 16-bit windows
   in 432 of 2048 ffn.0 channels (`Measure-KokoroConvWindows`, against `docs/generator60x-16bit-design.md` "Conv").
   Fix: every linear's windows take their LSB from the input's own calibration peak (identity gain above 1 is allowed:
   `New-KokoroAdaInLeaky16Steps -Identity` computes K x / 2^15 with an int32 K and clamps); `ConvertTo-KokoroConvPack`
   throws when a channel's offset exceeds half the window. ffn.0 after the fix: L 5..8, no window over int16.
3. Shared int8 weights differed by one LSB between repeats (float32 fold by the input LSB): `ConvertTo-KokoroConvPack
   -WindowLsb` quantizes in weight units, so a weight shared by layers with different input LSBs packs to the same bytes
   (checked byte for byte across the 12 repeats).
4. Attention context 2-8 dB below its model with only q rescaled: k rescaled per head too.

| Decoder + generator + source | done (one job) | none for short text |
| Phone chain | each job runs alone | host program: phonemizer -> ALBERT -> predictors -> alignment -> decoder + generator -> AAudio |

First end-to-end text to audio for a short sentence (ALBERT T <= 32 tokens, decoder <= 96 frames, about 2.3 s of audio):
about four to five sessions of this size (ALBERT accuracy, about one; predictors and text encoder, two to three, the
LSTM the largest piece; phone chain, about one). Publishable benchmarks (the six passages up to 28 s, both phones, time
to first audio) add long-sequence work already recorded as blocked: ALBERT weight streaming past 32 tokens, decoder and
generator halo-tiled streaming, breath-group pipelining, SM8635 runs: about three to five more sessions.

No pruning found so far removes one of these blockers: the LSTM recurrences and long-sequence streaming are inherent to
the model's shape. Narrowing ALBERT's FFN (2048 -> 1024 frees 1.5 MB of VTCM) would postpone ALBERT weight streaming
for longer sentences; that is the one cut on the table, allowed without retraining under AGENTS.md "Model changes".

## Pitfalls turned into checks

PowerShell names are case-insensitive: `$T`/`$t`, `$H`/`$h`, `$C`/`$c`, `$Vt`/`$vt` collided four times in ad-hoc code
this session; diagnostics now live in the entrypoint, where `Test-PowerShellCasePair` runs. `[byte] -shl 8` stays a byte
(cast to int first). An empty array returned through `$( )` or an `if` expression arrives as `$null` or unrolled (assign,
then pass). In array literals the comma binds tighter than `+`. Match a file's own line endings (or use the editor) when
splicing text. `0xFFFFFFFF` is -1 in PowerShell. A command text containing `Remove-Item` with a computed path is blocked by
the session hook: write such code with the editor.
